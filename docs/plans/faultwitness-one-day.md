## สิ่งที่ต้องเปลี่ยนตอนพอร์ต (จุดที่ต้นแบบใช้กับของจริงไม่ได้)

1. **ใช้เวลาที่ collector ได้รับผล (`received_at`) ตัดสินข้อมูลเก่า แทน `finished_at` ของ probe** — กรณี "นาฬิกาเครื่อง A เพี้ยน" จะทำให้ A ดูเหมือนส่งผลมาจากปี 2019 แล้วถูกตัดสินว่าขาดการติดต่อ ทั้งที่จริงควรได้ "เฉพาะจุด A"
2. **ปิดปัญหาที่ต้นแบบค้างไว้ (ใน commit message)**: streak นับตามคำตัดสิน ไม่ใช่ตามชนิดหลักฐาน → DNS ที่หลักฐานอ่อน (TCP ก็ไม่ผ่าน, อาศัยเทียบกับ B) ได้ระดับ "ยืนยัน" ต่อจากรอบก่อนที่หลักฐานแข็ง · แก้ด้วยการนับ streak ด้วยคีย์ที่รวมฐานหลักฐาน (`dns|A|ip` กับ `dns|A|peer`) โดยคง `keys` ที่ใช้เทียบคำตอบไว้เหมือนเดิม · เขียน test ที่ล้มก่อนแก้ (เคส "เสียสองอย่างพร้อมกัน" ช่วงที่สอง)
3. **round id ต้องเรียงได้ด้วย string** — ใช้ `r-000123` (เติมศูนย์) เพราะ `diagnose` ใช้ `.sort()`
4. **เก็บไว้เฉพาะ N รอบล่าสุด** (เช่น 60 รอบ) ก่อนเรียก `diagnose` เพราะต้นแบบวิเคราะห์ใหม่จากทุกแถวทุกครั้ง
5. ข้อความภาษาไทยใน `explain()` คงไว้ตามต้นแบบ

### การจับคู่ข้อผิดพลาดของ Node → `error_type` (ทดสอบแล้วบน Node 22)

| การตรวจ | วิธี | ผลล้ม → `error_type` |
| --- | --- | --- |
| `http` | `fetch(url, { signal: AbortSignal.timeout(t) })` ใช้ชื่อโฮสต์เสมอ ไม่แปลงเป็น IP | `TimeoutError` → `timeout` · `cause.code` `ECONNREFUSED` → `refused` · `ENOTFOUND`/`EAI_AGAIN` → `dns_error` · `CERT_*`, `DEPTH_ZERO_SELF_SIGNED_CERT`, `UNABLE_TO_VERIFY_LEAF_SIGNATURE`, `ERR_TLS_CERT_ALTNAME_INVALID` → `tls_cert` · HTTP status ≥ 500 → ล้ม (`http_status`) |
| `dns` | `dns.promises.lookup(host)` แข่งกับ timer | หมดเวลา → `dns_timeout` · `ENOTFOUND`/`EAI_AGAIN` → `dns_error` |
| `tcp` | `net.connect({ host: ip, port: 443 })` + timeout | `timeout` · `ECONNREFUSED` → `refused` |

อะไรที่ไม่รู้จัก → เก็บ code ดิบไว้ใน `error_type` (ต้นแบบแสดงค่าดิบอยู่แล้ว)

## ความเสี่ยงที่รู้อยู่แล้ว

- **OS cache DNS** ทำให้เหตุ DNS ไม่แสดงผลทันที → ล้าง cache หลังเปลี่ยน resolver และจดไว้ในขั้นตอนแล็บ
- **ไฟร์วอลล์บนเครื่องหลักปิดพอร์ต collector** → ทดสอบ `curl http://<หลัก>:<พอร์ต>/api/report` จากทั้งสอง probe ก่อนเริ่มแล็บ
- **`dns.lookup` ยกเลิกไม่ได้** (ใช้ getaddrinfo) → การแข่งกับ timer ให้ผลถูก แต่ thread ของ libuv อาจค้างจนหมดเวลาของ OS · ถ้ารอบชนกันให้เพิ่ม `UV_THREADPOOL_SIZE` ตอนรัน agent
- **site-x ต้องอยู่นอกเครือข่าย** ไม่อย่างนั้นเหตุ "ทางออกภายนอกถูกบล็อก" จะไม่กระทบ site-x และกฎ R2 จะไม่เกิด
